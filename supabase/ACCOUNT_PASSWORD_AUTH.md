# 앱·웹 일반 아이디 로그인 / 회원가입

2026-11-10 최종 요청: Google·Apple 유지, ‘계정으로 로그인’은 일반 아이디·비밀번호, 하단 회원가입은 아이디·비밀번호·비밀번호 확인. 앞선 이메일·비밀번호 신규 가입안을 대체한다.

## 사용자 동작

- 회원가입에 실제 이메일 주소를 요구하지 않는다.
- 아이디: 영문·숫자·밑줄(_) 4~20자. 앞뒤 공백 제거, 영문 소문자로 정규화하여 대소문자를 구분하지 않는다. 가입 시 이메일 모양/한글/기타 기호는 거부한다.
- 비밀번호: 신규 가입 입력 및 어댑터에서 8자 이상, 확인값 일치 요구. 비밀번호의 앞뒤 공백을 임의로 제거하지 않는다. 기존 로그인에는 새 최소 길이를 강제하지 않는다.
- 같은 아이디는 중복 생성할 수 없으며 중복 오류 시 기존 계정에 로그인된 것으로 처리하지 않는다.
- 서버 인증 세션을 `getUser`로 검증한 뒤 홈으로 이동한다. 이후 서버 UUID 기준 기존 찜·플랜 저장/복원 경로를 재사용한다.
- 이미 만든 이메일·비밀번호 계정은 로그인 아이디 칸에 기존 이메일을 입력할 수 있다. 신규 가입은 일반 아이디만 받는다. 기존 Google·Apple 사용자/저장 데이터는 옮기거나 덮어쓰지 않는다.

## Supabase 연동 설계

Supabase의 기본 비밀번호 인증은 이메일/전화번호를 식별자로 사용한다. 자체 비밀번호 DB를 만들거나 서비스 역할 키를 프런트에 넣지 않기 위해 일반 아이디를 `${정규화된아이디}@accounts.busandrop.invalid`라는 내부 식별 주소로 대응시킨다.

- `.invalid`는 실제 메일 발송용 도메인이 아니다. 사용자에게 실제 주소 입력/도메인 구입/SMTP 설정을 요구하지 않는다.
- 가입과 로그인에서 같은 순수 매핑을 사용한다. 이메일 필드의 Supabase 고유 제약이 중복 아이디를 막는다. 매핑 규칙/도메인은 배포 후 임의로 변경하지 않는다. 바꾸려면 기존 계정 로그인 마이그레이션이 필요하다.
- `user_metadata.username`도 저장하지만 편집 가능한 메타데이터를 인증 근거나 권한 판별에 사용하지 않는다. 별도의 공개 사용자 조회 테이블/RPC는 추가하지 않는다.
- 비밀번호 검증·세션 발급·잠금/제한은 Supabase가 담당한다. 비밀번호를 앱 상태, HTML value, 로컬 스토리지, 플랜/통계 데이터에 복사하지 않는다. 요청 완료 후 비밀번호 입력값을 제거한다.
- 내부 이메일 식별값은 수신/소유 확인이 되는 이메일로 취급하지 않는다. 일반 아이디 계정은 현재 이메일 기반 비밀번호 복구를 제공하지 않는다. 새로운 복구 수단은 후속 작업이다.
- 실제 이메일로 가입한 기존 계정과 일반 아이디 계정은 별도 주체다. 사용자의 실제 이메일과 아이디를 자동으로 연결하지 않는다.

## 운영 설정 확인

사용자가 User Signups → Confirm email OFF 및 저장 성공 화면을 제공했다. `/auth/v1/settings` 읽기 확인 결과 emailEnabled=true, signupDisabled=false, emailAutoConfirm=true.

일반 아이디 가입에는 이 상태가 필요하다. 확인 메일이 다시 켜져 세션이 발급되지 않으면 가입 성공으로 표시하지 않고 ‘계정 생성을 완료하지 못했어요’로 처리한다. 수신 불가능한 내부 주소로 메일 확인을 하도록 사용자에게 안내하지 않는다. 기존 이메일 계정에 대한 미확인 이메일 오류만 메일 확인 안내를 유지한다.

## 검증

- 전체 211개 테스트 통과. 아이디 정규화/로그인과 가입 매핑 일치, 잘못된 아이디/짧은 비밀번호의 공급자 호출 전 거부, 중복 가입, 없는 세션의 성공 오인 방지, 기존 이메일 로그인 호환, 요청 중 로그아웃 경합, 입력 확인 및 비밀번호 제거 검사 포함.
- 운영 인증 서버에 무작위 없는 아이디로 비밀번호 로그인 1회: 400 invalid_credentials 확인. 새 계정 생성/메일 발송 없이 내부 식별 주소가 로그인 입력으로 처리되는지 확인했다. 이는 실제 가입 성공 검증을 대신하지 않는다.
- 실제 로컬 운영 셸에서 하단 회원가입 버튼 → 아이디·비밀번호·비밀번호 확인 입력폼을 시각 확인했다. /tmp/busandrop-username-signup.png.
- 실제 신규 일반 아이디 가입/재로그인/다른 기기 복원은 사용자 테스트가 남아 있다. 실제 사용자 비밀번호나 인증 토큰을 기록하지 않는다.

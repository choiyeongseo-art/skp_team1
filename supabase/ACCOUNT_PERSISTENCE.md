# BUSANDROP 계정 저장 (2026-11-09)

전용 인증 프로젝트: `yinxfrdkxohyttmkuaxa` (관광 데이터 프로젝트와 별도).

| 테이블 | 기본 키 | 저장 내용 |
|---|---|---|
| busan_account_preferences | user_id | 마지막 선택 언어, 갱신 시각 |
| busan_account_events | user_id + event_id | 저장 행사, 선택 지점, 저장 시각 |
| busan_account_plans | user_id + plan_id | 플랜 전체 JSON: 일정, 장소, 순서, 이름, 방문 완료 상태 |

세 테이블은 RLS를 켜고 authenticated 역할에 `auth.uid() = user_id`인 행만 CRUD를 허용한다. anon/public 권한은 회수했다. 실제 SQL Editor 조회에서 3개 모두 RLS=true, 본인 정책 1개, anon SELECT=false를 확인했다. 브라우저에는 publishable key만 사용한다.

## 동작

- Supabase SDK가 같은 브라우저의 세션을 유지·갱신한다. 서버 getUser 검증에 성공한 세션만 복원하고 로그인 화면을 건너뛴다. 로그아웃, 세션 만료/취소, 브라우저 데이터 삭제 시에는 재로그인이 필요하다.
- 계정 로그인 시 원격 행사·플랜·언어를 읽는다. 동일 계정은 다른 브라우저에서도 서버에 완료된 저장 내용을 불러올 수 있다.
- 플랜은 변경된 ID만 upsert/delete한다. 브라우저가 모르는 원격 플랜을 통째로 지우지 않는다.
- 실패한 쓰기는 계정 ID별 브라우저 대기열에 보관한다. 온라인 복귀 및 15초 주기 재시도. 마이에 불러오는 중/저장 중/저장됨/동기화 대기 상태 표시.
- 로그인 전 플랜·행사는 이 브라우저에서 처음 연결한 계정으로 1회 가져온다. 동일 ID의 기존 원격 플랜을 덮어쓰지 않는다. 다른 계정에 반복 가져오지 않는다.
- 로그아웃은 서버 데이터 삭제가 아니다. 게스트 저장 공간으로 돌아간다. 계정 간 플랜·행사 캐시와 대기열을 분리한다.
- 언어는 마지막 설정값을 저장한다. 모든 선택의 시간별 분석 로그는 아직 수집하지 않는다.

## 범위와 한계

- 이 문서는 계정별 기능 데이터 저장이다. 분석용 이벤트 테이블/대시보드는 별도 작업이다.
- 동시 접속해 같은 플랜을 편집하면 마지막 서버 쓰기가 반영된다. 실시간 공동 편집/충돌 병합은 구현하지 않았다.
- 독립적인 장소 북마크는 계정별 로컬 캐시이며, 요청 범위인 저장 행사와 만든 플랜만 클라우드 동기화한다.
- 이메일 인증 메일 템플릿/발송 환경은 별도 설정 사항이다. 실제 이메일 수신 및 여러 실기기 간 종단 검증은 이 작업의 자동 테스트로 대체할 수 없다.
- 테스트는 SDK 모의 응답 기반으로 복원·격리·오프라인 재시도·본인 행 삭제를 검증한다. SQL Editor에서는 테이블/정책/권한을 실제 확인했다.
